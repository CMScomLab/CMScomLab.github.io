# CMScomLabブログの作成・更新

## 必ず行うこと

1. `git status --short --branch` で作業状態を確認し、既存の変更を保護する。新規作業では、指定がなければ `codex/` 接頭辞の作業ブランチを作る。
2. `docs/blog/posts/` の関連エントリーと直近のエントリーを読み、語調、見出し、用語、リンク方法を合わせる。
3. 新規記事を `docs/blog/posts/YYYY-MM-DD-<slug>.md` に置き、次のフロントマターを設定する。
   - `date`
   - `authors`（通常は `terapyon`）
   - `categories`
   - `tags`
   - `slug`
   - `title`
4. フロントマターの `title` と本文のH1を一致させ、導入部の後に `<!-- more -->` を入れる。
5. サイト内の記事には、投稿ファイルからの相対リンクを使う。外部リンクには原則としてHTTPSの正規URLを使う。
6. 研究、特許、顧客、未公開技術に関する記述は、ユーザーが明示した公開範囲を越えて具体化しない。断定の強さも提供された事実に合わせる。
7. `uv run mkdocs build --strict` を実行し、リンク、フロントマター、Markdown、MkDocs設定を検証する。失敗した場合は原因を直して再実行する。
8. 最後に変更ファイル、ブランチ名、検証結果を報告する。コミット、push、PR作成は依頼された場合だけ行う。

## 推奨すること

- 冒頭だけで記事の主題と読者が得られる情報が分かるようにする。
- 関連する過去記事を自然な文脈で1件以上リンクし、サイト内で内容をたどれるようにする。
- 一文を長くしすぎず、誇張、過度な自己評価、言い訳に見える説明を避ける。
- 技術用語は既存記事の表記に合わせ、初出時に必要最小限の説明を加える。
- 箇条書きや表は、比較や要点整理に役立つ場合だけ使う。
- 画像を追加する場合は `docs/assets/images/YYYY-MM-DD-<slug>.*` を基本とし、意味のある代替テキストを付ける。
- 公開前に差分を読み直し、日付、固有名詞、相対リンク、未公開情報の混入を確認する。
